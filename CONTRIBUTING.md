# Contributing

CronTrace is an initial CLI release candidate with a deliberately conservative model. Correctness, evidence quality and maintainability come before feature breadth. No contributor or adoption claims are implied by this repository.

## Local development

Use Node 24.x and npm:

```sh
npm ci
npm run verify
```

`verify` runs strict TypeScript checking, ESLint, unit/integration tests, a production build and E2E installation of a local tarball into a temporary directory. E2E installation may resolve dependencies from npm; offline audits themselves disable fetch in these tests. `npm test` is fast module testing; `npm run test:e2e` includes compilation. No GitHub credentials or live API calls are required by CI. `npm pack` prepares a local artifact without publishing it.

Read [architecture](docs/ARCHITECTURE.md) and [methodology](docs/METHODOLOGY.md). Source is in `src`, tests in `test`, synthetic reproducible examples in `examples`. Do not hand-edit the lockfile; pin reviewed dependency versions. Keep package and `src/version.ts` versions aligned.

## Changes and review

Open a focused issue/PR explaining a concrete problem and before/after behavior. For a matching or evidence change, supply a minimal adversarial timeline with independently specified expected classifications; demonstrate that the previous behavior fails. Do not replace expectations with snapshots generated by the algorithm under test. Preserve unknowns when evidence cannot justify certainty. Run the complete verification command after integration, plus relevant targeted checks during development.

Use synthetic data by default. Real evidence requires permission and provenance; review workflow source, identifiers and notes before sharing it. Never commit credentials or private bundles. Security reports follow [SECURITY.md](SECURITY.md). Keep edits scoped; do not publish packages or merge without maintainer review.

New schedule semantics need authoritative references and boundary cases. API changes need mocked pagination/rate/error/partial-evidence tests. Avoid convenience flags that silently assert historical facts. Document behavior and limitations with the code, and update `docs/IMPLEMENTATION_STATUS.md` for substantial work.

Participation follows [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md). Contributions are made under the repository's MIT license. Maintainer availability may vary with school commitments; no response or support SLA is promised.
